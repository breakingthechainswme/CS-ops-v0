01 — What this tool is

A structured prompt engineering assistant

The Master Prompt Builder is a step-by-step form that helps you build complete, professional AI prompts without having to remember frameworks or start from a blank page every time.

Instead of typing a vague instruction into Claude or ChatGPT and hoping for the best, you fill in guided fields — audience, platform, constraints, tone, format — and the builder assembles a fully structured prompt from your answers. Every prompt it outputs follows the same consistent structure, which makes results more predictable and easier to improve over time.

💡
What it is not: The builder is not an AI itself. It doesn't generate content — it generates the prompt you use to get content from Claude, ChatGPT, or any other AI tool. Think of it as a briefing form that turns your creative direction into precise instructions for an AI.

The core workflow in one sentence

Fill in the builder → copy the assembled prompt → paste it into your AI tool → get consistent, structured output.

02 — The 8 prompt types

Choose the right type first

The very first step is selecting a prompt type. This determines every step that follows — the fields shown, the questions asked, and how the final prompt is assembled. Picking the wrong type won't break anything, but picking the right one gives you more relevant fields.

✦
Idea
Generate batches of content ideas. Best starting point — use this first when you don't have a topic yet.
↗
Hook
Write opening lines for Reels, carousels, ads, or emails. Use after you have an idea to build from.
▣
Script
Full video or carousel scripts. Use after you have both an idea and a hook if linking them.
∞
Generator
Multi-format output — captions, subject lines, post batches. Good for bulk content creation.
◌
Analysis
Audience research, competitor review, performance breakdowns.
⇄
Workflow
Multi-step process prompts — SOPs, automation sequences, systems.
□
Framework
Reusable prompt templates you can apply across different topics.
⚙
Tooling
Business operations — lead generation, bookkeeping, client communication prompts.
⚠️
Idea, Hook, and Script are the pipeline types. They are designed to link together — an idea feeds into a hook, a hook feeds into a script. The other five types (Generator, Analysis, Workflow, Framework, Tooling) are standalone and don't have pipeline fields.
03 — Step-by-step walkthrough

What each step is asking for

Every prompt type moves through 6–7 steps. Here is what each step means and what to put in it.

01
Type select
Choose which of the 8 prompt types you're building. The rest of the builder adapts to your choice.
If you're not sure, start with Idea. It's the broadest starting point.
02
Foundation
The core brief — your topic or niche, which platform(s) it's for, what the content goal is, and how much output you want. This is the most important step — everything else is layered on top of it.
Be specific on the topic. "Small business bookkeeping" outperforms "finance" every time.
03
Strategy / Mechanics
Type-specific depth. For Idea: trend approach and differentiation. For Hook: psychological mechanisms and emotional triggers. For Script: framework and structure. This is where the prompt gets opinionated.
Even if you're unsure, pick something. A wrong constraint is easier to adjust than a blank one.
04
Audience
Who the content is for. Target audience description, awareness level (how well they know the problem), emotional triggers that resonate, and pain points. The AI uses this to make output feel targeted rather than generic.
The pain points field is worth filling in carefully — it's the most direct way to stop generic AI output.
05
Constraints
Hard rules for the output. Output format, tone, words to avoid, reasoning approach, and self-check instructions. This step is what separates a prompt that produces consistent results from one that varies wildly.
"Words to avoid" is underused. Put in the words that make AI content sound like AI: seamlessly, leverage, game-changer, unlock, delve.
06
Iteration
Tracking fields for your Notion library. Domain, version number, score (fill this after testing), priority, and which Notion databases to link it to. Also where you write iteration notes — what changed in this version.
Domain and Version are required before you can build. Everything else is optional but worth filling in if you're saving to Notion.
✓
Required fields: Foundation (topic + platform + goal) and Iteration (domain + version) are the only mandatory fields. Everything else improves output quality but won't block the build.
04 — Linking prompts together

The Idea → Hook → Script pipeline

The three content pipeline types are designed to build on each other. You don't have to use all three — you can start at any stage — but when you do link them, the output at each stage is grounded in the work you already did.

How to pass an idea into a Hook build

On the Hook Foundation step, you'll see a field called Prior idea (optional). Paste the full assembled prompt output from your Idea build here — or just paste the specific idea you chose from the AI's output. The builder injects this as a SOURCE IDEA block in the hook prompt, so the AI writes hooks that are grounded in that specific angle rather than generating hooks based on the topic alone.

💡
What to paste: You have two options. Paste the entire assembled Idea prompt (from the dark code block on the output screen) for maximum context — or just paste the specific idea text from the AI's response if you've already run it and chosen one. Either works.

How to pass a hook (and idea) into a Script build

On the Script Foundation step, you'll see two separate optional fields:

FieldWhat to pasteWhat it does
Prior hookThe specific hook line you chose from the AI's hook outputTells the AI to use this exact line as the script's opening — it won't rewrite it
Prior ideaThe original idea brief or assembled Idea promptKeeps the script true to the original angle, audience, and goal

You can fill one, both, or neither. If you fill the Prior hook field, the AI opens the script with your chosen hook. If you also fill the Prior idea field, the whole script stays oriented around the original brief — the hook, the body, and the CTA all point in the same direction.

Full pipeline example — step by step

  1. 1
    Build an Idea prompt. Select Idea type, fill in your niche (e.g. "bookkeeping for small businesses"), platform, goal. Build it. Copy the prompt and run it in Claude. Pick the best idea from the output.
  2. 2
    Build a Hook prompt using that idea. Select Hook type, fill in the topic, then paste the idea you chose into the Prior idea field on the Foundation step. Build it. Run it in Claude. Pick the strongest hook.
  3. 3
    Build a Script prompt using that hook. Select Script type. Fill in the topic, format, structure. Paste your chosen hook into Prior hook and your original idea into Prior idea. Build it. The script will open with your exact hook and stay aligned with the original brief.
  4. 4
    Save all three to a project. On the output screen, use the Save to Project panel to link each stage to the same project. The pipeline tracker at the bottom of the builder shows which stages are complete and lets you revisit any prompt.

Using the context carry-over (automatic field mapping)

There's also a faster option on Step 1 — the Paste prior context link under the type cards. If you paste a previous prompt output here before selecting a type, the builder will automatically extract the topic, platform, audience, and tone and pre-fill the matching fields when you continue. This works best when the prior prompt has clearly labeled lines like TOPIC:, PLATFORM:, AUDIENCE:.

This is an auto-fill shortcut. The Prior idea and Prior hook fields on Foundation are the deliberate, explicit way to link stages — use those when you want full control.

06 — Projects and the pipeline tracker

Tracking a piece of content from idea to script

Projects are completely optional. Every build works standalone — you can build prompts, copy them, and use them without ever creating a project. Projects are only useful when you want to track a piece of content through the full Idea → Hook → Script pipeline and be able to come back to any stage later.

Creating a project

Click + New project on Step 1 or in the Project Pipeline Tracker panel at the bottom of the page. Give it a name that identifies the content piece — e.g. "Bookkeeping Reel — March" or "Lead Gen Campaign Q2". One project = one piece of content.

The pipeline tracker

The tracker panel at the bottom of the page always shows all your projects. Each project displays a three-stage pipeline: Idea → Hook → Script. Stages that have been saved show in green. Click any completed stage node to expand it and see the prompt preview, copy the prompt, or load it as context for the next build.

⚠️
Projects only auto-save Idea, Hook, and Script types. The other five types (Generator, Analysis, Workflow, Framework, Tooling) don't appear in the pipeline tracker — save those using the snapshot function instead.

Saving a build to a project

After building, the output screen shows a Save to project panel. Select the project from the dropdown and click Save. If you don't have a project yet, click "+ Create project to save" to create one inline. The tracker updates immediately.

Using a saved stage as context for the next build

In the tracker, expand any completed stage and click Use as context →. This resets the builder to Step 1 with the prior prompt pre-loaded into the context carry-over box. Select your next type and hit Continue — the builder auto-fills topic, platform, audience, and tone from the prior output.

07 — Snapshots

Saving versions of your work mid-build

Snapshots are lightweight saves of the current prompt at any point during a build — before you've finished all the steps. They're useful when you want to experiment with different constraint combinations without losing a working version.

Click Save snapshot in the Session Tools card at the bottom of any step. The builder saves the current assembled prompt (with whatever fields are filled so far), the version note, and a timestamp. You can save up to 10 snapshots per session.

Click View snapshots to see all saved snapshots. Each one shows the title, timestamp, and iteration notes, with a Copy prompt button to retrieve it.

💡
Snapshots vs Projects: Snapshots are temporary in-session saves — good for capturing a work-in-progress state. Projects are persistent saves of completed builds linked to a pipeline. Use snapshots while building; use projects for finished output.
08 — Saving to Notion

Adding a completed prompt to your Prompt Library

The builder is designed to output directly into a Notion Prompt Library. Here's the exact process:

1
Open Notion Prompt Library → New entry
Create a new page in your Notion Prompt Library database.
2
Paste the suggested title
Copy the title from the builder output screen and paste it as the entry name. Format is: Type — Platform — Topic — Version.
3
Fill Notion field columns
Use the Notion Fields summary on the output screen as your reference — Domain, Prompt Type, Platform, Version, Score, Status, Priority, Linked to. Or use Copy all fields and paste the whole block.
4
Paste the full prompt into the page body
Open the Notion entry page. Paste the assembled prompt (from the dark code block) into the page body. This is the actual prompt text you use.
5
Paste the layer summary below it
Paste the layer summary below the prompt as build notes — documents every choice that produced this version so you can replicate or adjust it later.
6
Fill Score after testing
Run the prompt in your AI tool. Grade the output 1–10 in the Score column. Use iteration notes to record what worked and what to change in V2.
✓
Tip: Leave Score blank on first save. Only fill it after you've actually run the prompt and seen the output quality. A score without a real test is just a guess.
09 — Tips for better prompts

What actually moves the needle

The fields that matter most

In rough order of impact on output quality:

  1. Topic / niche — specific beats vague every time
  2. Pain points — the fastest way to stop generic AI output
  3. Words to avoid — eliminates the most common AI tells
  4. Self-check instruction — makes the AI review its own output before returning it
  5. Prior context fields — keeps linked prompts coherent
  6. Reasoning approach — use Step-by-step for complex tasks, Fastest path for bulk output

Words to always put in "Words to avoid"

seamlessly, leverage, game-changer, unlock, delve, it's important to note, in today's fast-paced world, revolutionary, cutting-edge, dive deep, at the end of the day, paradigm shift, synergy, holistic, empower, transformative

These are the words that make AI output sound like AI output. Excluding them forces more natural language.

Version discipline

Start every new prompt at V1. Only increment to V2 when you've actually tested V1 and identified specific changes to make. A V3 prompt that was never tested isn't a V3 — it's a guess with extra steps. The Score column in Notion is where version decisions should come from.

10 — FAQ

Common questions

Do I need to create a project to use the builder?
No. Projects are optional. You can build, copy, and use prompts without ever creating a project. Projects are only useful when you want to track a content piece through multiple pipeline stages and come back to prior work.
What's the difference between a snapshot and saving to a project?
Snapshots are in-session saves of a work-in-progress prompt — useful for preserving a state before making changes. Project saves are permanent records of a completed build linked to a content pipeline. Use snapshots while building, projects when you're done.
Can I use a hook I already have — one I didn't build with this tool?
Yes. Just paste it directly into the Prior hook field on the Script Foundation step. It doesn't have to come from the builder. Same with the Prior idea field — paste any idea, brief, or prior AI output you want to build from.
The context carry-over didn't fill my fields automatically. What happened?
The auto-fill looks for specific labeled lines in the pasted text — TOPIC:, PLATFORM:, AUDIENCE:, TONE:. If the prior output doesn't have those labels, auto-fill won't find anything to map. The raw text still gets appended to the prompt as PRIOR CONTEXT, so the AI still has it — you just won't see the fields pre-filled. Use the Prior idea / Prior hook fields on Foundation for more reliable explicit linking.
What does "Send to Claude ↗" do?
It copies the assembled prompt to your clipboard and shows an alert to paste it into Claude. If you're running the builder inside Claude's artifact viewer, it may attempt to send the prompt directly. In all other environments (GitHub Pages, local file, Notion embed) it's a copy + prompt to paste manually.
I lost my progress after refreshing the page. What happened?
The builder auto-saves your current state to localStorage, which persists across refreshes. However, localStorage doesn't survive clearing browser data, private/incognito mode, or some embedded contexts (Notion embeds may not share localStorage with the main browser). If you're doing important work, use Save snapshot before leaving the page — snapshots are also stored in localStorage but are kept separately from the build state.
Can I use the same idea for different content formats?
Yes — that's one of the intended workflows. Build an Idea prompt once, run it in Claude, get a list of ideas. Then start separate builds for each format you want: one Hook build for Reels, another Hook build for email subject lines, a Script build for the video. Each builds from the same source idea but is independently optimized for its format.
The builder says a field is required but I don't know what to put in it.
The only hard requirements are Topic (or Outcome for general types) on Foundation, and Domain + Version on Iteration. For Domain, pick the closest category — you can change it in Notion later. For Version, start at V1 if it's new. If you're stuck on Topic, use the broadest accurate description of what you're making content about — you can refine it in iteration notes after testing.
How do I improve a prompt that isn't giving good results?
Start with the Constraints step — specifically Words to avoid, Self-check, and Reasoning approach. Then look at Audience — shallow pain points produce generic output. Finally check the Prior context fields if you're linking pipeline stages — if the source material is vague, the downstream prompt will be too. Increment the version, note what changed in Iteration notes, and re-test.
